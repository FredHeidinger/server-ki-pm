Schritt 5: In Claude Code eintragen

Einmal in einem Terminal ausführen (Pfad anpassen, falls du einen anderen Ordner gewählt hast):

claude mcp add --scope user kipm -- python "%USERPROFILE%\.kipm\kipm_mcp.py"

Prüfen in Claude Code mit /mcp: dort muss „kipm“ als verbunden erscheinen. Jeder neue Chat hat dann die Werkzeuge kipm_projekt, kipm_auftraege, kipm_auftrag_anlegen, kipm_uebernehmen, kipm_fortschritt, kipm_rueckfrage, kipm_ergebnis und weitere. Freigabe und Abnahme gibt es dort bewusst nicht.

Schritt 4: Dem Chat die Regeln geben

Diesen Text einmal in den Chat einfügen:

Du bist über Server-KI-PM an die zentrale Auftragssteuerung angebunden. Die Datei .kipm im Projektordner enthält Adresse und Zugang; lies sie nicht vor und kopiere sie nirgendwohin. Prüfe den Zugang mit: python kipm.py projekt

Regeln:
- Vor jedem Anlegen zuerst: python kipm.py auftraege  (nichts doppelt anlegen)
- Neue Aufgabe nur als Entwurf: python kipm.py auftrag-anlegen --titel "…" --text "…" --modul <modulkennung> --prio hoch|mittel|niedrig
- Arbeiten nur an freigegebenen Aufträgen nach Übernahme: python kipm.py uebernehmen A-<nr> --revision <rev>; Ziel, Schreibumfang und Abnahmekriterien aus python kipm.py lesen A-<nr> sind bindend.
- Unterwegs: python kipm.py fortschritt A-<nr> --revision <rev> "…"; bei offenen Fragen rueckfrage, bei Problemen hindernis oder fehler. Antworten des Menschen stehen in python kipm.py lesen A-<nr>.
- Zum Schluss: python kipm.py ergebnis A-<nr> --revision <rev> --zusammenfassung "…" --datei "pfad@commit" --pruefung "befehl: ergebnis" --luecken "…"
- Änderungswünsche am Auftrag mit vorschlag melden; Umfang, Freigabe und Abnahme änderst du nie selbst.

Schritt 2: Anfragen stellen

Jede Anfrage trägt die Kopfzeile Authorization: Bearer <Schlüssel>. Antworten sind JSON mit ok und entweder Daten oder fehler. Verändernde Anfragen tragen anfrage_kennung: gleiche Kennung mit gleichem Inhalt wirkt nie doppelt.

curl -sS --cacert kipm-root.crt -H "Authorization: Bearer {% if neuer_schluessel %}{{ neuer_schluessel.schluessel }}{% else %}SCHLUESSEL{% endif %}" {{ server_url }}api/auftraege/
Methode und PfadZweck
GET /api/projekt/Projekt, Module, Arbeitsorte
GET /api/auftraege/Alle offenen Aufträge; ?nur_meine=1, ?alle=1
POST /api/auftraege/anlegen/{titel, beschreibung, modul?, prioritaet?, erzwingen?, anfrage_kennung}
GET /api/auftraege/<id>/Auftrag mit Revision, Kriterien, Aktivität
POST /api/auftraege/<id>/uebernehmen/{revision, anfrage_kennung}
POST /api/auftraege/<id>/fortschritt|rueckfrage|hindernis|fehler|vorschlag|pruefbericht/{revision, text, anfrage_kennung}
POST /api/auftraege/<id>/ergebnis/{revision, zusammenfassung, dateien[], pruefungen[], luecken, anfrage_kennung}
GET /api/entscheidungen/, POST …/vorschlagen/, POST …/<id>/bestaetigen/Entscheidungen des Projekts

Fremde Projekte antworten 404, Konflikte und veraltete Revisionen 409. Es gibt keine Schnittstelle für Freigabe, Prüferwechsel, Abnahme oder Umfang.
